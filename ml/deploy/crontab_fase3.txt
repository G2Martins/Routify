# Fase 3 (cron) — 10 rodadas/dia, mas os HORÁRIOS mudam por dia da semana
# (campo dia-da-semana do cron), não repetem o mesmo relógio todo dia.
#
# Por quê: repetir as mesmas 10 horas todo dia só dá amostra boa daquelas 10
# horas — nunca pega 9h, 14h, 20h, 23h etc. Variando por dia, em ~1 semana a
# cobertura passa por quase o dia inteiro (5h-23h), e como a semana se repete
# ~4x no mês, cada combinação dia-da-semana × faixa de horário ainda acumula
# várias amostras — não perde poder estatístico, ganha cobertura.
#
# Sáb/dom têm horário mais tardio de propósito (padrão de trânsito de fim de
# semana é diferente — gente sai mais tarde, picos de manhã cedo não existem
# do mesmo jeito) — é um recorte interessante por si só pra comparar com dia
# de semana.
#
# Cada rodada: 11 pares, ~1-2 min, RAM/CPU desprezíveis (chama a API já
# rodando via HTTP, não carrega grafo/modelo).
#
# Instalar na EC2:
#   crontab -e
#   cola tudo abaixo (ajusta o caminho do venv se for diferente)
#
# Conferir que o cron roda em horário de Brasília:
#   timedatectl   (deve mostrar America/Sao_Paulo; senão, ver nota no fim)
#
# Log de cada rodada vai em ml/artifacts/fase3_cron.log (acumulado); dados em
# ml/artifacts/fase3_comparacao_cron.csv.
